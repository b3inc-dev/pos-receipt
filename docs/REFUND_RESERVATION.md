# 返金の予約（返金の前に、実際の返金方法を決めておく）

T の決定（2026-11-23、カード）: POS 純正で返金する前に、「実際の返金方法」を注文に予約しておく。純正の返金ができたら、いま受けている `orders/updated` の知らせでその返金に結び付け、後から返金方法を変更したのと同じ記録を自動で作る。新しい webhook は足さない。後から「返金方法変更」タイルの一覧で返金方法を変更するやり方も残す。

返金方法変更の決まりは #106（`docs/DECISIONS.md` D27）と同じ。金額は純正の返金額で固定し、分割でき、最後の行は残り。Shopify では返金せず、精算は元の手段から実際の手段へ移すだけ。残りを超えて返金方法を変更することはしない。

T の追加の決定（2026-11-23 15:40 UTC）: 管理画面の「特殊返金設定」→「返金の予約」で店ごとにオン・オフする（初めはオフ。Ciara から先に使う）。予約には「返金する金額」を必ず入れ、純正の返金額がそれと同じときだけ自動で返金方法を変更する。違うときは「要確認」にする。

T の変更（2026-11-24）: 分割しない予約は金額を入れない。純正で返金した額の全部を選んだ返金方法に変える（`expectedAmount` は 0 ＝「金額の条件なし」として保存。DB の形は変えない）。「返金する金額」は分割するときだけ入れ、そのときだけ純正の返金額との一致を確かめる。画面の上に取引の合計と元の支払方法ごとの金額を出す。分割で返金額が合わないときの扱いは T に確認中（今は前のとおり「要確認」）。

## 店舗での流れ

1. 「返金方法変更」タイルの一覧の右下の「返金前登録」を押し、注文を選ぶ（「返金の予約」がオンの店だけ出る。T 2026-11-24）。POS の注文の画面のアプリのメニューや、一覧から注文を開いて「返金方法変更」を押してもよい
2. まだ純正で返金していない注文では「返金前登録」の画面が出る（「返金の予約」がオフの店では出ずに、今までの登録の画面になる）。返金方法を選び（「分割」で金額と返金方法の行を足せる。分割のときだけ「返金する金額」を入れる。最後の行は残り）、「予約する」
3. 「戻る」で注文の画面に戻り、いつもどおり POS 純正で返品・返金する
4. 返金が終わると、アプリが返金方法変更を自動で作る。注文をアプリで開き直すと、調整履歴に出ている

予約は、その注文で使う前のものを 1 つまで置ける。直すときは、取り消してから入れ直す。予約は、予約した日（店のタイムゾーン）のうちにできた返金にだけ使う。その日が終わったか、見つかった返金が別の日のものなら使わない（期限切れ）。

### 予約の状態

- `pending`（予約中）: 返金を待っている
- `applied`（返金に使いました）: 返金方法変更を作った（`appliedRefundId`・`appliedEventIds`）
- `needs_review`（要確認）: 自動では作らなかった。店の人向けのわけを `reviewReason` に入れる。「返金方法変更」タイルの一覧から返金方法を変更する
  - 返金が複数の支払方法に分かれていた
  - 分割の予約で、返金額が予約の「返金する金額」と違った
  - 予約の金額の合計が返金額より大きかった
  - 返金方法変更が途中で止まった（残りの決まりなど）
- `cancelled`（やめた予約）、`expired`（期限切れ）

ほかの登録と同時に書いて断られたとき（`CONCURRENT_UPDATE`）は、予約を使う前のまま残し、次の知らせか POS で開いたときに続きを当てる。予約のメモは顧客データの削除要求（`customers/redact`）で消す。

元と同じ手段の行（例: 現金で払って現金で返す）は、返金方法変更が要らないので作らない。その額は使ったことにする。承認の設定がオンの店では、返金方法変更は今までどおり承認待ちになる。
