# レシートプリンターの58mm補正

2026-11-24。対象は本アプリがPrinting APIで出す帳票。Shopify標準レシートの設定は変更しない。

## 公式情報と実機確認の区別

[Shopify公式：mC-Print3の印字欠け](https://help.shopify.com/en/manual/sell-in-person/hardware/receipt-printers/mC-Print3/troubleshooting)は、POSの印刷幅は80mmのみで、58mm用紙では一部が欠けると案内している。公式の対処は80mm用紙であり、本アプリの逆補正を推奨・保証する記述ではない。

MCP31LBの58mm印字で、同じ100 CSS pxの外枠が横8mm/縦12mm、右R/100%が途中で欠けることを利用者が実測した。診断Bでは配置幅64%・横1.5倍・縦等倍により、正方形の縦横比と右端の表示が良好であることを利用者が実紙で確認した。変換がShopify・ドライバー・プリンターのどの段階で発生するかは未確認。

公式情報から同じ用紙幅の制限が分かるmC-Print3系でも、この補正で必ず直るとはしない。他の機種・接続・メモリスイッチ等の設定は実機未検証。「58mmで横に縮む・右端が欠ける」という症状を見て選び、通常帳票でも確認する。機種名や接続プリンター名から自動選択しない。

## 管理画面

印字設定の「プリンターに合わせる」で一度選ぶ。AppSetting `print_settings` の `receiptPrinterProfile` に保存。既存店は未設定＝標準。用紙幅設定は従来どおり、精算/点検/領収書と販売/ギフトでそれぞれ解決する。

- 標準：既存の印字・帳票別プレビュー補正を維持。
- mPOP・58mm：印字HTMLは変更せず、実測100px=12mmに基づく400pxのプレビューを全4帳票で共用。
- 58mmの横縮み・右端欠け（MCP31LBで確認）：出力時に64%幅のラッパーを横1.5倍にする。描画後96%を使い右に4%を残す。縦は変えない。

80mmではいずれの機器補正も適用しない。画面上の実寸や字体の一致を保証するものではない。手書きCSSの固定幅・絶対位置などは個別調整が必要な場合がある。

この版の設定はShopifyストアの全店舗・全端末で共通。機種が混在するストアでは補正不要の端末にも適用されるため、標準のままとする。端末/接続プリンター別の選択は未実装。混在運用の制約を設定欄にも表示する。

## 印字とプレビュー

- 精算/点検・領収書・販売/ギフトの印字ルートの最終出口へ適用。ブロック、新生成/手書きLiquid、旧帳票、描画失敗時のfallbackも同じ出口を使う。
- 発行済み領収書の保存HTMLは書き換えず、出力時の設定で変換。原本データ・金額・件数・印字済み記録の扱いは維持。
- 専用マーカーにより二重適用を防ぐ。今回の診断Bの `mcp-correction` ラッパーも検出して重ねない。他の手書き補正は自動判別できないため、共通設定を使う前にコード側の補正を外す。
- MCPプレビューは内部600px（48mm ÷ 8mm ×100）で同じラッパーを描く。その後横2/3・縦等倍を模擬し、画面に収まるよう外側を等比縮小。内容の折り返し幅は600×64%=384px。mPOPは400px。送信用に横へ伸ばした文字をそのまま表示しない。
- プレビュー個別調整は詳細内に残す。58mmの共通機器設定があればそちらが優先。既存保存値は消さない。

## 品質とリリース境界

単体/DOMテスト、印字ルートのモック統合テスト、設定保存と4エディタの読み込み、PC/390px幅のローカル画面で確認。通常帳票全種・実Shopify埋め込み画面での最終印字照合は未実施。診断紙の成功と帳票全面実機検証を区別する。本番反映は専用PRの品質確認・独立レビューと承認後。
