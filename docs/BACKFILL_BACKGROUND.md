# 過去データ取り込みを裏で進める（2026-11-22）

T さんの決定（2026-11-22）: 管理画面の「過去データ取込」（`/app/backfill`）は、画面を閉じても裏で進むようにする。UI ルール v1.1 の 12章。

## 動き

- 「取込開始」を押すと、選んだロケーション・月の日付の一覧（今日より先の日は入れない）を進み具合として保存し、1 日分のジョブを積む。
- ジョブは 1 日を取り込み（取込済みの日は飛ばす。今までの画面と同じ）、次の日のジョブを約 1 秒あとに積む。1 店で動くのは 1 本だけ。
- 「停止」は止める知らせを書き、次のジョブが止まる（取り込み中の日は終わらせる）。
- 「続きから再開」は、失敗した日と途中の日だけを取り込み直す。「選んだ月で最初から取り込む」で別の月・店にできる。
- 再開するときは runId を新しくする。前の鎖のジョブが pg-boss のやり直し待ち（30 秒〜）で残っていても、runId が違うので何もせずに止まり、鎖が 2 本にならない（同じ日を 2 回集計しない）。
- 本番に出す PR の本文には「`BACKFILL_QUEUE` を入れなければ裏の道が動く（`0` で前の形）」と 1 行書く。
- 画面を開いている間は 3 秒ごとに進み具合を読み直す。10 分動いていなければ「要確認」にし、「続きから再開」を出す。
- Shopify に入れない（トークン切れなど）ときはジョブが失敗し、pg-boss が最大 3 回やり直す（その日は「処理中」のまま。次も同じ日から）。

## 保存先（DB の変更なし）

| AppSetting の key | 中身 |
|---|---|
| `backfill_run` | 進み具合（runId・ロケーション・月・状態・日ごとの結果）。`app/utils/backfillRun.ts` の `BackfillRun` |
| `backfill_run_stop` | 止める知らせ（`{ runId }`。始めるとき・再開するときに `null`） |

新しい表・migration は無い。キューの表は pg-boss が自分の schema（`pgboss`）に作る（売上サマリーの Webhook のキューと同じ）。

## 設定

| 環境変数 | 既定 | 意味 |
|---|---|---|
| `BACKFILL_QUEUE` | （オン） | `0` / `false` で使わない。画面は今までどおり、開いている間だけ 1 日ずつ送る |
| `DATABASE_URL` | — | 無いときも使わない |

pg-boss の接続は売上サマリーのキューとは別の 1 つ（接続は最大 2 本）。
