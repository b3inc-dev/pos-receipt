# 領収書の運用ルール（店舗スタッフ向け）

POS で領収書（宛名・但し書きつき）を発行するときの運用ルールです。アプリの仕様は [BUSINESS_RULES.md](./BUSINESS_RULES.md) §12、保護顧客データの扱いは [PROTECTED_CUSTOMER_DATA_OPS_CHECKLIST.md](./PROTECTED_CUSTOMER_DATA_OPS_CHECKLIST.md) を参照してください。

## 1. 但し書きにお客様の名前を入れない

- 但し書きには **品目・用途だけ** を書きます（例:「お買上品代として」「書籍代として」「飲食代として」）。
- **お客様の名前（個人名・「〇〇様」など）は但し書きに入れません。** 名前が必要なときは **宛名** の欄に入れます。
- 会社名・団体名も、宛名に入れれば足りるものは宛名に入れます。
- 管理画面で変えられる「但し書きのデフォルト」にも、人の名前を入れません。

| 良い例 | 悪い例 |
|--------|--------|
| 宛名: 山田 太郎 様 ／ 但し書き: お買上品代として | 宛名: （空）／ 但し書き: 山田太郎様 お買上品代 |
| 宛名: 株式会社〇〇 ／ 但し書き: 書籍代として | 宛名: 株式会社〇〇 ／ 但し書き: 〇〇部 佐藤様分として |

## 2. 理由: お客様の削除依頼でも但し書きは消さない

決定（T・2026-11-23 03:00 JST、連絡帳 Issue #39）: **領収書の但し書きは、お客様の削除依頼（Shopify の `customers/redact`）が来ても消さない。** そのかわり、但し書きにお客様の名前を入れない運用にする。

お客様の削除依頼が来たとき、アプリがその注文について消すもの・残すものは次のとおりです。

| 項目 | 削除依頼のあと |
|------|----------------|
| 領収書の宛名 | 消す（再印字では空。発行履歴では「—」） |
| 特殊返金のメモ | 消す（金額・日時は残す） |
| 領収書の但し書き | **残す**（発行履歴・再印字・データ開示の対象に残る） |
| 金額・注文番号・発行日時など | 残す |

但し書きに名前を書くと、削除依頼のあとも名前が残ってしまいます。だから名前は必ず宛名に入れます。

> 補足（2026-11-23 時点のコード）: 宛名を空にする・特殊返金のメモを消す処理は #41 のブランチに入っていて（PR #75。発行履歴の「—」は PR #85・draft）、main にはまだありません。main の `webhooks.compliance.tsx` は宛名を `[redacted]` に置き換えるだけです。#41 が main に入ると上の表のとおりになります。但し書きはどちらでも消しません。

## 3. アプリ側の現状（未実装のもの）

- POS の但し書き欄・管理画面の但し書きデフォルトは自由入力で、名前が入っているかどうかの入力チェックや注意書きは **ありません**。このルールは店舗の運用で守ります。
- 入力欄への注意書きの表示などをアプリに入れるかは未定（別 Issue / PR で扱う）。

## 4. 店舗への周知

- 新しく POS を使うスタッフには、領収書の発行手順と一緒にこのルールを伝えてください。
- 但し書きに名前を入れて発行してしまったときは、店長に伝えてください。アプリには発行済みの但し書きを直す・消す機能はありません（対応の手順は未定）。
