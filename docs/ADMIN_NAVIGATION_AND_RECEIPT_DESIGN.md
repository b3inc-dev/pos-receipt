# 管理画面のメニュー・レシート設定の統合

2026-11-24。既存設定の保存先、印字の優先関係、集計計算を維持して入口と操作を整理。

## メニュー

- レシート：4帳票の基本設定・デザイン・プレビュー、領収書履歴、プリンター/印字設定。
- 精算：計算・確定に関する設定と履歴。帳票編集の重複入口は置かない。複数の調整種別を扱う履歴はメニュー/見出し/戻りリンクとも「調整履歴」。
- 店舗：店舗一覧、支払方法マスタ。
- レポート：集計しない一覧から売上サマリー、店舗/チャネル予算、各設定を選ぶ。トップのレポート入口で自動集計しない。
- システム：一般設定を入口にする。料金プランを開くことを通常の設定への入口にしない。既存の自社用/開発ストア向け表示制御は維持。

グループタブは全ページで共通部品を直接配置し、カード外枠を付けない。基本/履歴画面はPolarisの標準幅。精算履歴だけのfullWidthを除去。デザインの2列編集と予算の日別マトリクスは広い幅を使うが、1200pxを上限とする。モバイルの余白・テーブル/カード切り替えは既存ルールを維持。

## レシート設定

`/app/receipt-layouts` を「レシートのデザイン」とし、各帳票の画面に既存の基本設定を集約。

- 販売：販売/ギフト共通の有効化・用紙幅、標準デザインの見出し/末尾文/表示項目。
- ギフト：販売/ギフト共通の有効化・用紙幅、標準ギフトの見出し/末尾文/注文番号。
- 領収書：既定の但し書き・宛名敬称、発行元情報、既存テンプレートの詳細値、精算/点検と共通の用紙幅。既存ReceiptTemplate行と版を使い、実際に内容を変更したときだけ版を更新する。発行済みReceiptIssue/保存HTMLは更新しない。
- 精算/点検：共通用紙幅とプレビュー種別/見本の差額表示。これらの見本設定は実際の集計に影響しない。

使うデザインは「標準」「作成したデザイン（ブロック・コード）」で選ぶ。既存receipt_layout_print_v1の値を継承し、開くだけで切り替えない。標準へ戻しても作成コードを消さず、編集途中の切り替えでも下書きを保持。基本設定とデザインは保存の帯1つでまとめて保存/破棄する。

標準プレビューは印字用rendererを使う。旧設定画面で見せていた装飾のうち、実際の標準rendererで未対応の項目を印字対応済みと推測して追加しない。詳細値は失わず保持し、見本で反映を確認する旨を表示。作成したデザインはブロック/手書きコードの指定を優先し、固定文字の発行元情報などはデザイン側も編集する。旧CSS/既存Liquidを自動書換しない。

旧5URL（sales-receipt-layout、sales-receipt-settings、receipt-template、receipt-print-layout、settlement-print-layout）のGETは対応する統合画面へ302。埋め込みqueryを保持。既に開かれた旧画面からのPOSTは互換維持する。

新しい保存はDB transactionで基本設定/レイアウト/使用設定を一括保存。共有行を部分更新し、他帳票の値を上書きしない。基本設定の保存時点比較で競合を知らせ、Serializable競合は上限付きで再試行する。schema migrationなし。

## レポートの待機

`/app/reports` は認証のみの軽量な入口。`/app/sales-summary` も画面枠/メニューを先に出す。既存の管理画面集計処理は `salesSummaryAdmin.server.ts` へ移し、認証/プラン制御を維持した `/app/sales-summary-data` で取得する。

集計中/取得失敗でもグループタブを表示し、設定やチャネル管理に移動できる。全画面を覆う読み込み帯は既存共通LoadingIndicatorへ統一。streamTimeoutの延長で待たせる方式ではない。計算/キャッシュ/再取得フラグの意味は維持（再取得後のredirectだけ表示画面のパスを明示）。並び順の適用以外は既存集計関数を変更しない。画面を離れた後のサーバー計算の強制中断は追加しない。

## 店舗一覧の表示順

上下ボタンまたは1始まりの表示位置入力で操作し、一覧の保存の帯で保存。絞り込み中も非表示店舗のID/相対順を失わない。表示位置は全店舗中の位置。保存するのはLocation.sortOrderのみで、機能/金額/返金先の設定は変更しない。

店舗所有権/重複ID/元のsortOrderを検証し、一括transactionで保存。競合や途中失敗は全件取り消す。休止店舗など一覧外の行は保持。並び順は管理の店舗一覧・POSの店舗選択・管理売上サマリーの店舗行へ反映（計算は同じ）。既存の個別編集の並び順とも共有する。
